## Architectural notes for future work

### `emit_to_parent_thread` couples to `ThreadState`

`workflows/emit.py` imports `deerflow.agents.thread_state.ThreadState` and
compiles a noop graph against it (lazily, to avoid an import cycle).
Today emit only targets lead_agent threads, so this is fine. If we add a
second agent type whose threads can host workflows, lift the schema to a
parameter.

### Hints inbox is single-process

`workflows/hints_inbox.py` is a `dict[str, list[str]]` guarded by an
`asyncio.Lock`. Restart-fragile (gateway restart drops queued hints) and
single-process (multi-replica gateway would lose hints across replicas).
Both limitations match the existing constraint that bg workflow tasks
themselves don't survive gateway restart. Swap for a sqlite sidecar or
redis when we need either property.

### `_wait_for_parent_idle` polls 4 Hz

Background runner polls `RunManager.has_inflight(parent_tid)` every 250ms
for up to 60s before each emit. Edge cases:

- If RunManager is unset (langgraph dev mode, unit tests), the wait is a
  no-op — emit fires immediately. Documented in `try_get_default_run_manager`.
- If parent thread is genuinely stuck for longer than 60s, we emit
  anyway and log a warning. Trade-off is documented in
  `background.py`'s docstring.

### `serialize_channel_values` strips internal channels

Three categories filtered: `__pregel_*`, `__interrupt__`, `branch:to:*`.
The `branch:to:*` filter was added 2026-04-28 because emit's noop graph
bleeds them into checkpoint values. If you add a new internal-channel
prefix to LangGraph, update this filter.
